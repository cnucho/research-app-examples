# 정책문제로 시작하는 합성자료 모음

**SYNTHETIC · 모든 관측값·개인·지역·사업 규칙은 가상이다.** 실제 조사 응답을 가명처리한 파일이 아니다. 이 자료로 계산한 값을 현실의 정책효과로 인용할 수 없다.

## 사용 순서

1. `registry.json`에서 정책문제와 관측 단위·시점을 확인하고 한 사례의 한 버전을 고른다. `v01`, `v02`는 같은 문제의 서로 다른 가상 수집자료다.
2. 선택한 폴더의 `README.md`, `datapackage.json`, `codebook.csv`를 함께 읽는다. `data/`에서 CSV 또는 SAV 한 형식만 올린다. 같은 관측값의 두 형식을 이어 붙이지 않는다.
3. 대화창에 정책 담당자의 질문을 입력한다. 분석명이 아니라 알고 싶은 변화, 대상, 비교집단, 측정시점을 설명해도 된다.
4. AI가 제시한 비교 대안과 추가 확인사항을 검토한다. 결합이나 변수 계산이 필요하면 결합키·자료 수·미결합 행·계산식이 기록되는지 확인한다.
5. 일반 결과창과 전문가용 결과창의 수치가 같은 실행 결과를 가리키는지 확인한다. 단위, 표본수, 비교대상, 불확실성, 한계가 함께 제시되어야 한다.

## 포함된 정책문제

| 문제 | 수집자료 구조 |
| --- | --- |
| 무더위쉼터 운영 확대와 온열질환 신고 | 여러 해 동안 같은 가상 지역을 관측한 지역 패널·정책대장 |
| 청년 구직 교통비 지원과 노동시장 결과 | 각 조사차수에 다른 사람을 뽑은 반복횡단면·지역 정책대장 |
| 디지털 직업훈련과 후속 근로소득 | 참여 전 조사·사업참여 기록·후속조사 |
| 주택 단열지원과 전력사용량 | 신청 평가점수·지원 규칙·전력사용 기록 |
| 디지털 민원교육과 후속 과제 수행 | 교육 전 특성·교육 기록·중간 설문·후속 수행평가 |
| 폭염예방 교육시간과 노동자 건강·업무 지표 | 기초 노출·교육시간·동일 관측기간의 후속 지표 |

각 사례의 정책 규칙과 문항은 새로 작성했다. 실제 공개자료에서 확인한 필드명은 `source_variable`, 이름을 바꾼 개념 차용이나 자체 설계 여부는 `source_match`에 기록했다. 확인하지 않은 영문명을 공식 변수명이라고 표시하지 않았다.

## 제공하는 메타데이터

| 파일 | 내용 |
| --- | --- |
| `datapackage.json` | Frictionless Data Package v1 형식의 파일 목록·자료형·기본키·외래키·행열 수·해시 |
| `codebook.csv`, `codebook.json` | 변수명·설명·단위·코드·결측·측정시점·파생식 |
| `questionnaire.csv` | 새로 작성한 합성 문항·응답 형식·대상·건너뛰기 조건 |
| `value_labels.csv` | 코드별 라벨과 사용자 결측 여부 |
| `source_crosswalk.csv`, `sources.json` | 공식 출처와 합성 변수의 대응, 확인 범위·한계 |
| `manifest.json` | 배포본 SHA-256·생성 seed·라이브러리 버전·라이선스 |

CSV는 UTF-8 BOM 형식이다. 숫자처럼 보이는 식별자는 코드북대로 문자열로 읽어 앞자리 0을 보존한다. SAV는 라벨과 사용자 결측코드를 담는다. 별도 결측코드는 모든 열에 일괄 적용하지 말고 해당 변수에만 적용한다. 결측 제외나 대체는 자동 실행 규칙이 아니다.

## 다른 앱에서 쓰기

루트 등록부에서 패키지를 찾아 `entrypoint`가 가리키는 `datapackage.json`을 읽으면 파일과 스키마를 찾을 수 있다. CSV는 R·Python·SPSS·Stata 등에서 읽을 수 있고 SAV도 제공한다. 특정 앱의 결과 캐시나 내부 데이터베이스에 묶이지 않는다. 다른 앱이 등록부를 자동으로 읽게 하는 연결 기능은 그 앱에서 별도로 구현해야 한다.

현재 정책 MCP 앱 `cnucho/mcp-special-analysis-tools` 0.2.0에 대한 실제 실행 검증은 별도의 verification receipt에 기록한다. 입력 묶음은 분석 답안이나 미리 계산한 보고서를 재생하지 않는다.

## 해석과 평가의 범위

코드는 생성·계산·기록·수치와 파일 정합성 확인을 수행한다. 방법 선택, 진단의 의미, 인과적 설명, 정책적 결론은 AI 또는 연구자가 맡는다. 검증기의 통과가 인과추론의 타당성을 인증하지 않는다.

일반 입력 ZIP에는 평가자의 잠재결과·생성식·참고 실행계획을 넣지 않는다. 별도의 evaluator ZIP과 공개 생성 소스에는 그런 정보가 있다. 비교평가를 할 때는 분석 AI에 일반 입력 묶음만 제공해야 한다. 이는 평가 운영상 분리이며 접근통제나 비밀보장 기능은 아니다.
