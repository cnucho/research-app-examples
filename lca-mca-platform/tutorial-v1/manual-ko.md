# LCA–MCA 따라하기 · tutorial-v1

이 매뉴얼과 영상은 같은 [가상 예제 자료](https://github.com/cnucho/research-app-examples/releases/tag/lca-mca-tutorial-v1)를 사용합니다. **미리 만들어 둔 분석 결과는 없습니다.** 각 버튼을 누를 때 앱이 현재 자료로 계산합니다. 예제는 실제 연구의 타당성 인증이 아닙니다.

## 준비

1. Release에서 `mobility_survey.csv`, `codebook.json`, `item_map.csv`, `manifest.json`을 내려받습니다. SPSS 흐름을 연습하려면 `mobility_survey.sav`를 CSV 대신 사용합니다. 같은 프로젝트에 CSV와 SAV를 동시에 넣지 않습니다.
2. `manifest.json`의 SHA-256과 받은 파일을 비교합니다. 파일이 다르면 다른 버전의 매뉴얼과 섞지 않습니다.
3. LCA–MCA 앱을 열고 **자료** 탭에서 `mobility_survey.csv`와 `codebook.json`을 선택해 **불러오기**를 누릅니다. 화면에 **행 1800, 열 21**이 보이는지 확인합니다. `income_group=99`는 코드북에 표시된 응답 거절이며, 기본 연습에서는 바꾸지 않습니다.

## 연습 A: LCA 잠재유형

1. **연구문제** 탭에 `응답자의 이동 태도 유형은 무엇인가?`를 입력합니다. **분석 경로**에서 `LCA: 잠재유형`을 고릅니다. **지표 후보**에 다음을 정확히 붙여 넣습니다.

   ```text
   att_cost,att_convenience,att_environment,att_safety,att_digital,att_transit,att_flexibility,att_ownership
   ```

2. **분석 계획 후보 만들기**를 누릅니다. **대상**과 **가중치 변수**는 비워 둡니다. `survey_weight`가 파일에 있다는 사실만으로 가중 적합을 하는 것은 아닙니다.
3. **자료** 탭에서 파일과 코드북을 불러왔는지 확인합니다. 문항 연결까지 연습하려면 `item_map.csv`를 선택하고 **문항 연결 검토**, 이어서 **문항 연결 확정**을 누릅니다. 이 단계는 선택 사항이지만 연결을 시작했다면 확정해야 적합할 수 있습니다.
4. **변수 진단**과 **전처리** 탭에서 상태를 읽습니다. **전처리 제안**은 후보를 표시할 뿐 원자료를 바꾸지 않습니다. 이 기본 경로에서는 임의의 유목 통합을 승인하지 않습니다.
5. **LCA** 탭에서 `att_` 8개를 지표로 고릅니다. **계층 탐색**을 누릅니다. 간편 모드는 K=1~3, 초기값 5회, 최대 반복 80회의 예비 탐색입니다. 성공하지 않은 실행은 선택하지 않습니다.
6. **모형 검토** 탭에서 성공한 실행과 BIC 후보를 확인합니다. 예제 검증에서는 K=2가 수렴했고 K=3은 수렴하지 않았습니다. 실제 화면의 실행 상태와 QC를 확인하고, 수렴한 후보를 골라 **진단 계산**을 누릅니다. 경고는 해석에서 검토합니다. 차단 사유가 없다면 **연구자가 이 실행을 승인한다**를 체크하고 **모형 선택**을 누릅니다. BIC 최솟값만으로 자동 승인은 하지 않습니다.
7. **보고서** 탭에서 질문·문항 라벨·분석 준비 내용을 읽고 **검토자**를 적습니다. 세 확인 항목을 실제로 검토한 후 체크하고 **검토 기록**을 누릅니다. **승인된 최종 산출물**을 누른 뒤 `project_export.zip`을 내려받아 `report.docx`와 탐색 HTML을 확인합니다. 검토 전에 최종 문서를 시도하면 거부되는 것이 정상입니다.

## 연습 B: MCA 범주 관계

처음부터 새 세션 또는 새 프로젝트로 시작합니다. LCA 실행이나 승인을 MCA 승인으로 대신하지 않습니다.

1. 같은 CSV·코드북을 불러옵니다. **연구문제**에 `응답자의 이동 서비스 선택 범주는 어떻게 함께 나타나는가?`를 쓰고 `MCA: 범주 관계`를 고릅니다. **지표 후보**에는 다음을 씁니다.

   ```text
   choice_commute,choice_priority,choice_service,choice_trip,choice_info
   ```

2. **분석 계획 후보 만들기**를 누릅니다. **MCA** 탭에서 위 5개만 활성 변수로 고르고 **MCA 실행**을 누릅니다. 사용 N이 1,800인지, 차원표·범주표·범주 지도가 실제로 나타나는지 확인합니다. 지도상의 가까움은 인과효과가 아닙니다.
3. 결과를 읽고 **이 MCA 결과를 승인**을 누릅니다. **보고서** 탭에서 새 질문과 라벨을 검토·기록한 뒤 **MCA 최종 문서**를 누릅니다. `project_export.zip`에서 새로 계산된 `report.docx`와 MCA 근거를 확인합니다.

## MCP 경로

MCP에서는 같은 버전의 파일을 사용해 `lca_create_project` → `lca_import_data` → `lca_profile_data` → `lca_run_models` 또는 `lca_run_mca` → 근거·QC·방법별 승인 → `lca_export_artifacts` 순서로 실행합니다. 로컬 stdio는 허용된 파일 경로를, HTTP는 승인된 파일 바이트를 `filename`과 `file_base64`로 전달합니다. HTTP 서버가 GitHub URL을 자동으로 읽거나 다른 MCP의 개별 응답을 자동 전송하지는 않습니다. 최종 문서의 질문·라벨 검토 조건은 웹과 같습니다.

## 결과가 다를 때

파일 해시·앱 버전·지표 목록·실행 설정을 먼저 비교합니다. K=3 실패를 성공으로 취급하지 않습니다. 질문이나 자료를 바꾼 뒤에는 이전 승인·다운로드를 재사용하지 않습니다. `report.docx`가 거절되면 화면의 QC, 대상, 승인, 검토 기록을 확인합니다. 새로 실행한 수치를 영상의 한 장면과 억지로 맞추지 않습니다.
